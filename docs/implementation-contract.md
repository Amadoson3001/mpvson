# Implementation contracts

This is a real first release, not a UI-only demo. Windows and Linux share one Flutter application backed by libmpv through media_kit. Native desktop builds, OS title bars and file pickers. The primary agent handles dependencies, platform runners, final integration and documentation.

## Ownership

- Playback agent: `lib/domain/models/**`, `lib/data/services/playback_service.dart`, `lib/data/repositories/**`, `lib/ui/player/player_controller.dart`, `lib/main.dart`, playback/session tests.
- Interface agent: `lib/app.dart`, `lib/ui/core/**`, `lib/ui/player/views/**`, `lib/ui/player/widgets/**`, UI widget tests.
- Updates agent: `lib/data/services/update_service.dart`, `lib/domain/updates/**`, `tool/**`, update tests and `docs/updates.md`.

Only the primary agent edits pubspec, analysis options, root README, platform files and CI.

## Playback contracts

`lib/domain/models/media_entry.dart`: immutable `MediaEntry` with `String id`, `String path`, `String title`, `Duration position`, `Duration duration`, `DateTime lastPlayed`, and serialization/copyWith as appropriate. `path` supports local filesystem paths and http(s) URIs. For history use canonical source identity (`canonicalSource`, fragment-free), with a unique queue id for duplicate sources.

### Source validation

`lib/domain/models/media_source.dart` owns one validator for every input path — command line, drag and drop, file dialogs, URL field and restored sessions. `MediaSource.validate(raw)` returns `MediaSourceValidation` (`source`, `isValid`, user-readable error) and accepts local paths, Windows drive paths, `file:` URIs and the `media source` network schemes in `MediaSource.networkSchemes` (`http`, `https`). Any other scheme is rejected with an explicit message instead of being reinterpreted as a local path. `MediaSource.redact(source)` strips credentials, query and fragment from network URLs for display, diagnostics and scrubbing, and leaves local paths alone. `PlaybackSession` drops rows that fail this validation.

`PlaybackService` in `lib/data/services/playback_service.dart` wraps `media_kit.Player` and `media_kit_video.VideoController`. Constructor can have optional injection for tests. Avoid requiring native libmpv in model/repository tests. Provide `Player get player`, `VideoController get videoController`, and teardown. Use an abstraction/fake for controller tests where practical. `prepare()` performs the one-time bootstrap work (caching `engineVersion` and starting native event observation); opening a source must never await optional engine metadata, and readiness must not depend on `prepare()` completing.

`PlaybackSnapshot` (`lib/data/services/playback_service.dart`) extends the transport fields with source attribution: `int sourceStart` (the controller's request boundary), `String? nativeSource` (the source the engine actually reported) and `bool sourceLoaded` (set only once the engine confirms a loaded source). Progress and completion count only while `sourceStart` matches the active request and `nativeSource` matches the requested source; events attributed to a displaced or foreign source are ignored. libmpv does not notify `path` for refused loads, so failures are stamped through `PlaybackSourceIdentity.unresolvedRequest`.

### Engine event attribution

`lib/data/services/native_media_events.dart` is repository-owned and narrow: `NativeMediaEvents` exposes native `start`, `loaded` and `end` events with source identity, `interpretNativeProperty(property, value)` maps raw mpv property notifications to them, and `DisabledNativeMediaEvents` is the no-engine double. `lib/data/services/playback_source_identity.dart` holds the pure tracker (`beginOpen`, `beginStop`, `attachStarted`, `attachLoaded`, `attachEnded`, `boundaryCounter`, `attached`, `unresolvedRequest`). Identity is assigned when native events enter Dart rather than when media_kit callbacks fire, because the production adapter stamps callbacks with the current source counter. Native behaviour and its probe (`test/native_source_probe_test.dart`, opt-in) are documented in `docs/native-source-probe.md`.

The engine can announce one load with `path` **twice**; the second announcement is treated as a reload of the same source, so the load is unconfirmed again until the track list or duration confirm it and progress restarts at zero. The duration, however, belongs to the engine's stream rather than to one load, and the engine does not re-notify an unchanged value; a `started` event therefore keeps the last known duration instead of clearing it (`applyNativeEvent` in `playback_service.dart`, covered by `test/native_event_state_test.dart`). Snapshots are published through `lib/data/services/snapshot_emitter.dart` (`SnapshotEmitter`) rather than added to the synchronous broadcast controller directly, because a listener may issue a command that publishes again — a completion handler stopping the engine — and a nested add throws `Bad state: Cannot fire new event. Controller is already firing an event`. Nested publishes are queued, coalesced to the newest state, and delivered as soon as the dispatch that produced them finishes (`test/snapshot_emitter_test.dart`).

### Session persistence

`SessionRepository` in `lib/data/repositories/session_repository.dart`: default constructor, async init/load/save, OS application support directory, serialized and atomic writes. Provide optional directory injection for tests. Recover from missing/corrupt data without crashing.

Schema version 2 (`lib/domain/models/playback_session.dart`) adds the `saveNetworkUrls` consent flag. Version 1 files migrate forward; an unsupported future version, or a root whose required collections have the wrong type, rejects the primary and tries the backup (`SessionLoadResult.primaryRejected`, `note`), so a structurally invalid primary can never silently become an empty session. Recoverable rows survive normalization and out-of-range numbers are clamped. `lib/domain/models/session_progress.dart` holds the small atomic progress checkpoint (`revision`, `entryId`, `position`, `duration`) written to `progress.json`; a checkpoint older than the stored session revision is ignored and an equal or newer one wins.

URL privacy is opt-in. `PlaybackSession.withoutNetworkUrls()` and `SessionRepository.saveScrubbed(...)`/`scrubNetworkUrls()` remove stream entries from the primary file, the `.bak` recovery copy and `progress.json` while keeping local rows and local resume positions. Without consent, stream URLs stay in memory and are never written. All writes are atomic and serialized per directory; the cross-process lock retries without blocking and gives up at `SessionRepository.lockDeadline` (five seconds), so a held lock cannot hang shutdown.

Initialization awaits privacy migration, including a URL-shaped checkpoint left beside an otherwise clean session. Disabling URL persistence drains writes captured under the earlier consent setting before scrubbing. `SessionRepository.flush()` waits for active and pending session/checkpoint writes; controller shutdown drains both controller and repository queues before releasing services. Diagnostic redaction scans every embedded HTTP(S) URL before truncation, including URLs adjacent to punctuation and malformed URLs.

`QueueSnapshot` caches at most eight searches and 20,000 matching indices with LRU eviction. Immutable chunked entry lists share unchanged chunks between progress snapshots. A retained snapshot keeps its original metadata; a new snapshot can reuse matching indices but binds views to its own entries. Position-only engine ticks publish through `positionListenable`; timeline controls subscribe directly, while queue structure and current-row transport state use separate listenables. The queue widget remains stable across unrelated screen rebuilds.

Large imports validate and stage entries privately in batches of 100. They commit atomically only while the import, playback, transport-command and queue-structure revisions still match. Displayed rows and playback remain usable during staging. Appending preserves a pending open for the current source.

The thumbnail service owns the compressed memory cache, capped at 8 MiB. Queue rows can use `peek` for provisional artwork, then always request asynchronous source and sidecar fingerprint validation. Widgets do not retain a separate path-keyed byte cache. Extraction is serialized and interruption generations retry jobs interrupted by minimize, including rapid resume. Operation deadlines exclude time waiting for extraction, normalization and suspension. Pending disk writes coalesce by source digest and retain at most 8 MiB plus one active write, with a 256-task cap. Disk accounting rescans every 32 writes instead of scanning on each write.

Native video visibility suppresses texture publication while preserving playback. Hidden OpenGL acknowledgement uses the output's current rendering context. Windows lifecycle operations run in order on an owned executor; render admission closes before teardown, and all texture retirement callbacks finish before output destruction. Surface resize shares the same lock as raster reads. Linux idle render work holds an output reference and uses the same recursive render lock as raster rendering and teardown.

`verification/measure-minimize-cycles.ps1` verifies a long synthetic video through distinct queue paths, warms the queue, then records raw process and frame samples during repeated minimize/restore cycles. Its restore metric ends when Flutter consumes a fresh native video texture. It includes polling latency and does not measure OS compositor scan-out. A failed process or incomplete workload must fail the script.

`PlayerController` in `lib/ui/player/player_controller.dart` extends ChangeNotifier. Constructor `PlayerController({required PlaybackService playback, required SessionRepository sessions})`. Expose:

- `Future<void> initialize()`, `Future<void> saveSession()`, `Future<void> close()`.
- `Player get player`, `VideoController get videoController`.
- `bool hasMedia` indicates a source is loaded in the engine; a restored stopped queue may have a current entry without loaded media.
- `List<MediaEntry> queue`, `List<MediaEntry> recent`, `int currentIndex`, `MediaEntry? current`.
- `bool isPlaying`, `bool isBuffering`, `Duration position`, `Duration duration`, `double volume`, `double rate`, `String? error`.
- `bool shuffle`, `String repeatMode` (`off`, `all`, `one`), `bool canUndo`.
- `Future<void> openPaths(List<String> paths, {bool append = false})`, `Future<void> playIndex(int index)`.
- `Future<void> removeAt(int index)`, `Future<void> reorder(int oldIndex, int newIndex)` with Flutter reorder semantics, `Future<void> undoRemove()`, `Future<void> clearQueue()`.
- `Future<void> togglePlayPause()`, `Future<void> seek(Duration position)`, `Future<void> seekRelative(Duration delta)`, `Future<void> setVolume(double value)`, `Future<void> setRate(double value)`, `Future<void> next()`, `Future<void> previous()`, `Future<void> toggleShuffle()`, `Future<void> cycleRepeat()`.
- `List<AudioTrack> audioTracks`, `List<SubtitleTrack> subtitleTracks`, `AudioTrack currentAudioTrack`, `SubtitleTrack currentSubtitleTrack`, `Future<void> setAudioTrack(AudioTrack track)`, `Future<void> setSubtitleTrack(SubtitleTrack track)`, `Future<void> loadSubtitle(String path)`.
- `String engineVersion` if obtainable through mpv, otherwise a truthful fallback.

Handle stream cleanup, file-load errors, position throttling, resume after duration is known, transition saves, EOF progression, current item removal, missing files and close safely. No filesystem deletion when removing from queue. Playlist/history persistence must retain a stopped restored queue rather than autoplaying unexpectedly at launch.

## App and bootstrap

`lib/app.dart` exposes `MpvsonApp({super.key, required PlayerController controller, required UpdateService updates, required EngineUpdateService engineUpdates, bool desktopWindow = false})`. Set desktopWindow true only in real bootstrap, not widget tests. UI owns fullscreen using window_manager only when desktopWindow true. For tests provide an injectable video builder or a small app-shell widget to avoid loading native libmpv.

Core agent owns main.dart: initialize Flutter, MediaKit, window_manager, repositories/controller and updates; show native-title-bar desktop window with min size 720x480 and initial 1240x780; capture window close and await session persistence/dispose; support command line media paths. Error fallback UI must be readable if engine initialization fails.

## Update contracts

Mpvson has two independent update channels. The application package channel uses optional `MPVSON_UPDATE_MANIFEST` and remains a manual download and install. On Windows, the engine updater defaults to official stable releases. A stable release without a compatible x64 GPL libmpv ZIP produces `stableUnavailable` without changing the loaded engine. Development builds from the rolling `git-release` require an explicit, persisted channel choice. Channel changes are blocked during checks, downloads, saves and pending activation. An explicitly configured custom engine feed uses `MPVSON_ENGINE_UPDATE_MANIFEST` together with the base64 Ed25519 public key in `MPVSON_ENGINE_PUBLIC_KEY`. Linux continues to use the system libmpv and FFmpeg packages. The bundled DLL remains the development build recorded in the provenance file; choosing stable does not relabel or replace it.

Playback tuning is an optional `PlaybackSettingsCapability`, separate from the base playback interface. Bounded preferences round-trip through the session, including privacy scrubbing. Runtime writes wait for native video readiness, verify changed properties, cache confirmed values, and serialize/coalesce pending changes. Picture sliders commit at the end of the interaction. Settings > Video & audio contains tuning; Playback keeps speed and track selection. On-demand playback statistics do not add a background polling workload.

The controller owns shuffle over unique queue entry IDs. A cycle excludes already visited entries; repeat-off exhausts and stops, repeat-all starts another cycle, and repeat-one applies only to completion. Navigation follows confirmed playback history, bounded to 10,000 visits, rather than guessing the previous shuffled item. Reordering and duplicate source paths preserve entry identity.

`UpdateService` in `lib/data/services/update_service.dart` extends ChangeNotifier. Constructor `UpdateService({Uri? manifestUri, ... optional test injections})`. An omitted URL uses `String.fromEnvironment('MPVSON_UPDATE_MANIFEST')`; empty means no application update source is configured. No invented endpoint and no simulated available release.

- `bool configured`, `String currentVersion` default 0.1.0, `String status` (`idle`, `checking`, `available`, `downloading`, `ready`, `upToDate`, `error`, `unconfigured`), `double progress`, `String? error`, `ReleaseInfo? release`, `String? downloadPath`.
- `Future<void> check()`, `Future<void> download()`, `Future<void> openDownload()`.
- ReleaseInfo exposes `String version`, `String notes`, `String engineVersion`, `Uri downloadUri`, `String sha256`, `Uri? releaseUri`.

The application channel uses its versioned HTTPS manifest, Windows/Linux artifact selection, semantic version comparison, bounded requests, streamed downloads and SHA-256 verification. Reject redirects to HTTP, malformed manifests and bad hashes. Remove partial downloads safely. Application updates are downloaded for manual installation after closing Mpvson. Windows application archives include the app, plugins and a tested bundled mpv engine, which remains the fallback runtime. Linux application archives use the distribution's libmpv/FFmpeg runtime and must be tested against that runtime on a Linux runner.

The default Windows engine source reads `https://api.github.com/repos/mpv-player/mpv/releases/tags/git-release` over HTTPS. Select only the published `git-release` release's exact x64 MinGW GPL libmpv ZIP asset, validate its HTTPS GitHub URL and positive byte size, and require its GitHub `sha256:` asset digest. Verify both declared size and SHA-256 against downloaded bytes before staging. This trusts GitHub's HTTPS API and release metadata; it is neither an Ed25519 signature nor an Mpvson certification, and the upstream package is a development build. A custom signed feed is an optional alternative, selected only when both custom-feed build defines are configured. Its manifest uses `schemaVersion: 1` with `payload` plus a base64-encoded 64-byte Ed25519 `signature`. The signature covers only compact UTF-8 JSON for `payload`, with object keys sorted recursively. The payload contains engine version, notes, media_kit version, inclusive minimum app version, optional exclusive maximum app version, and one Windows artifact with an HTTPS URL, SHA-256 and byte size. The generated manifest is at most 256 KiB UTF-8; notes are limited to 80 KiB and the artifact URL to 4,096 characters. The artifact is a complete versioned engine ZIP with an exactly lower-case root `libmpv-2.dll` and the dependency files selected by the locked Windows media_kit CMake configuration, preserving supplied license/attribution files. Reject unsafe paths, links/special entries, missing or wrongly cased root DLLs, invalid compatibility bounds, signature, size or hash mismatches, ZIPs above 512 MiB, archives over 4,096 entries, and packages over 2 GiB uncompressed.

Verified Windows engine packages are staged under `<app support>/mpvson/engines/<engine-version>` and activate only after restart. A package is extracted and verified in a unique staging directory first; only then may it replace an existing directory, and only when that directory carries the updater's `.mpvson-engine.json` ownership marker for the same version. A directory without that marker is never deleted: staging fails with a message instead. Discarding a pending selection removes its unused staged package under the same ownership rule while retaining active and previous versions. Explicit rollback selects the previous compatible engine or the bundle for the next restart. Persist a boot-attempt marker before loading a pending engine and confirm it only after MediaKit and the playback controller initialize. On startup, use pending, active, previous and bundled candidates in that order. A pending candidate gets one boot attempt. If a custom engine fails native loading or playback-controller startup, persist its rejection/fallback and automatically restart in a clean process; MediaKit caches native bindings, so never switch DLLs inside an initialized process. Recovery is bounded, and a failure of the final bundled candidate is shown as a startup error. Clear a pending selection left unconfirmed by an earlier launch before falling back.

Selection recovery validates the stored records of the selection file and of its backup before choosing between them, so a parseable file whose records no longer resolve cannot hide a usable backup. An explicit bundled selection and an interrupted boot attempt always win over records from the backup, and recovery never proposes a pending install, so an engine this startup rejected cannot be selected again. Keep `lastRejectedVersion` in the selection state for that decision. For the custom engine feed, select it only when the manifest URL and the public key (or signature verifier) are both present; a one-sided configuration keeps the official source and reports `configurationWarning`, and a complete configuration that fails validation reports its error through `configurationError` instead of silently disabling engine updates.

Each staging attempt carries its own identity, marker and OS lease. A same-process active set also protects leases on systems whose locks are process-scoped. Sweep only owned, unlocked, unlinked attempts under the store lock. Failed commit cleanup checks the attempt identity and both selection files before deleting a final directory. Extraction cancellation is cooperative during preflight, output and hashing; close file handles and await worker exit before cleanup. Updater control paths are reserved in ZIP entries. Runtime validation hashes every executable dependency, including the main DLL once, and anchors that DLL's inventory digest to the selection record.

On Windows, configure the selected engine through the runner before MediaKit or video output initialization. The native bridge loads that exact module, and the CMake integration removes the video plugin's direct `libmpv.dll.a` link and resolves the plugin's render symbols from the same selected module. Do not restore a direct mpv link or allow the player and renderer to bind separate engine copies. The bridge requires mpv client API major version 2 and a version at least as new as the build headers. Do not replace arbitrary loose DLLs: one DLL without its matching dependencies and compatibility metadata is not a complete engine release. Linux engine updates remain system-managed.

Keep the optional application manifest and custom engine manifest independent. Do not claim that Mpvson hosts an engine feed, that upstream mpv builds are Ed25519-signed or Mpvson-certified, or that app packages install automatically. Linux uses the distribution runtime. The custom engine-manifest generator and tests cover integrity, compatibility, signatures, SemVer, malformed input and archive safety.

The maintainer provenance downloader follows at most four redirects among approved HTTPS GitHub asset hosts, rejects credentials and non-default ports, and enforces the declared size during streaming. It hashes incrementally and awaits disk writes. Idle and total deadlines bound network operations. A private partial file replaces the cache only after exact size and SHA-256 verification, preserving the prior cache on failure.

Thumbnail cache hits obey the same 12 MiB, 32 MP and 320x320 limits as new artwork. Legacy oversized cache images are normalized before use. Production image polling tests exercise the same helper used by native extraction, including partial writes, deadline, cancellation and oversize handling. Request cancellation releases consumers promptly; output cleanup and service disposal wait for the actual decoder teardown. Native disposal that never completes can still keep shutdown pending and requires native-process isolation to impose a hard teardown bound safely.

## Interface design

Modern, restrained desktop player. Dark bluish theme from AGENTS, clear hierarchy, generous video area, compact navigation, collapsible queue, polished empty state with open/drop, recent/resume entries with progress. Custom Flutter controls over GPU video, never ASS UI. Use real lazy lists, stable keys, accessible labels, tooltips, focus and keyboard shortcuts. Offer Open files, Open URL, subtitle picker, track selectors, speed/volume/seek, queue search/reorder/remove/undo, fullscreen, settings, and update status. Clear loading/errors, no fake metadata, no dead controls.

Responsive at 720x480 and 1240x780. Queue becomes a drawer when there is insufficient room. Keep native OS title bar. Main shortcuts: Space pause, hold Space 2x then restore rate, arrows seek/volume, Ctrl+O files, Ctrl+L URL, P queue, F11 fullscreen, Escape exit fullscreen, Delete removes selected queue item only when queue owns focus. Do not steal typing shortcuts from search/URL fields. Controls should auto-hide during active playback with no pointer interaction, and stay visible for pause, focus, open menus and seeking.

Native fullscreen reads preserve overlapping metrics notifications and run one trailing reconciliation after a resize, since the OS flag may change after the initial notification. Fullscreen auto-hide must work without broad position notifications; the widget regression supplies delayed platform responses and no playback ticks.
